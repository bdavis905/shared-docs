The flow

Steps 3–14 run straight through with no stops — every human touchpoint sits before the run fires or after the Doc lands.

Before the run
1 The request

An idea, a reel, a swipe link, or a rough brief comes in.

 person
2 The brief is written

The local Claude writes a 1–2 paragraph brief from the request — freeform. No template or schema is enforced anywhere; the skill file suggests showing it for a gut-check, but nothing waits for approval.

 local claude
The run — no stops from here to step 14
3 Fire

exodus genesis runs; the run record is created.

 local claude
4 Preflight + handoff

Checks the brand's primer and keys, snapshots the foundation, queues the job. Can fail here, can't pause.

 database
5–6 Seeds + primer selection

Loads any creative seeds, picks the primer for the requested awareness level. Brand steering text rides along.

 cloud script
7 Hooks — Mario voice

Primed with the brand primer, fed the brief + hook bank + seeds. ~20 hooks, with a second push for the more visceral ones.

 ad-hook-bot-1
8 Hooks — Infeed voice

Same inputs, runs in parallel with step 7. Another ~20 hooks. Both pools merge: ~40 total.

 in-feed-vsl-bot
9 Hook selection

A script picks the 2 most diverse hooks from the pool; the rest are discarded. (A manual-selection field exists in the code but nothing surfaces it yet.)

 cloud script
10 Body copy + headlines — Mario

Primer first, then hook #1 woven into the instruction with the brief and headline bank. Body copy (700–1500 words), then 4 headlines in the same conversation — there's no separate headline bot.

 mariobot
11 Body copy + headlines — Infeed

Same routine from hook #2. Extra passes add more rounds here.

 in-feed-vsl-bot
12 QA checklist

The 15-point automated check, with auto-fixes.

 cloud script
13–14 Doc written, run saved

Formatted into a Google Doc — one tab per variant, hook merged into the full ad — and the run completes.

 cloud script
After the run
15 Doc lands · edit menu

Per-variant edits are available — Natural-language / Shorten / Cut / Simplify / Make Better — each a quick pass by the edit-pass bot, written to a new Doc tab.

 person

Bot names as they exist in the system: the hook bot is ad-hook-bot-1 (not "new-hook-bot"), MarioBot's slug is mariobot, and headlines come from the body-copy bots — there is no standalone headline bot. The bots' system prompts live on the Genesis server; the app only sends them their inputs (primer, brief, instructions).

The three sources

Gambit, organic, and swipe are capture paths, not separate pipelines. Each extracts an idea differently, but all three land in the same Idea Bank — and from there one identical escalation feeds the flow above: the idea's description becomes the brief verbatim, its hook becomes a seed. The writers never know which source an idea came from.

SourceInputExtractionBank keys
Gambitfreeform brain-dumpgambit-splitter splits it into distinct ideasG1, G2…
OrganicIG / TikTok reel URLscrape + transcribe + read on-screen text → organic-idea-extractorO1, O2…
SwipeFB Ad Library URLscrape copy + transcript + overlay text → swipe-concept-extractorA1, A2…

One exception: writing from a previously saved competitor ad (--swipe <id>) bypasses the Idea Bank and this flow entirely — it routes to the separate remix pipeline.

The brief step

The brief is the least defined part of the system. There is no brief skill, template, or validation — the backend accepts any text. The only guidance is a note in the skill files:

"If the user gave you an idea, a winning ad, or a rough angle, you write the brief from it; surface it for a quick gut-check before running." — the genesis skill file

When writing from a banked idea there is no brief-writing at all — the idea's stored description ships to the bots word-for-word, exactly as it was captured.

Human touchpoints today

None of these block a run.

  • Idea Bank curation — list, edit, annotate, delete, and choose which ideas get written. The one-shot commands (--reel, --swipe-url) skip past it. · before the run
  • Brief gut-check — a convention in the skill files, not a mechanism. · before the run
  • Brand steering — persistent "always do / never mention" text in four lanes (body cold, body warm, hooks, headlines); rides into every run. · set once
  • Edit menu — per-variant passes after the Doc lands. · after the run

Natural seams

Places where the code already has a clean boundary — a stop could be inserted at any of these without reworking the steps around it.

  • After capture, before the brief — universal idea review (exists on the bank path; one-shot commands skip it). · between steps 1–2
  • After the brief, before firing — the gut-check becomes a real approval. · between steps 2–3
  • After the hook pool, before body copy — selection from all ~40 hooks instead of the script's 2. The manual-selection plumbing is already half-built; this is also the cleanest place to split the flow into a hooks stage and a copy stage. · between steps 9–10
  • After the drafts, before the Doc — review raw variants before formatting. · between steps 11–12
