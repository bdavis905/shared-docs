The mental model

The Genesis bots are the engine — Luke's trained copywriting and creative bots running on our server. You have two ways to drive that engine:

Manual · your key

Your Genesis API key

You call the bots directly from Claude Code with your own gen_ key, using your own recipes and skills (like the workshop pack). You pick the bot, build the conversation, shape the output.

Automatic · Exodus

Exodus

The done-for-you system. Pre-built pipelines run Luke's entire process — brief → hooks → body copy → headlines → Google Doc, plus image engines, the idea bank, and brand onboarding. It connects to the bots internally; you never configure a Genesis key for it.

Both are yours. Both can live in the same project folder. They don't share settings, and after the latest update they don't step on each other.

What changed in the update

First, run this in your project folder:

npx exodus update

Every Exodus skill is now namespaced (exodus-genesis, exodus-write, exodus-image…) plus one front door simply called exodus. Two rules to remember:

🚂 Say "exodus" to use Exodus. "Exodus, write me some ads." "Use exodus to make images." "Exodus, swipe this ad." Claude routes it to the right pipeline.

🔑 Say "genesis" to use the Genesis bots directly (not through Exodus). The word "genesis" by itself always means a direct call with your Genesis API key and your recipes — Exodus won't grab the request.

If you don't say "exodus," Exodus stays out of your way — your workshop skills and custom recipes run untouched in the same folder.

Heads-up: saying "genesis" works when your setup is present — your gen_ key from the members area saved as GENESIS_API_KEY in the folder's .env, plus your skills/recipes. Exodus does not install that key for you (its own Genesis access lives server-side, tied to your account). Auto-installing your key into the folder is on the roadmap.

Which one am I using right now?

However you've organized your folders — Exodus in one, your Genesis skills in another, or everything together — the tell is simply what you typed:

  • Said "exodus"? You're running an Exodus pipeline.
  • Said "genesis" or named a bot? That's a direct Genesis call with your own key and your own skills.

Before this update, Exodus's skills would grab requests meant for your own Genesis skills (and vice versa). Now they can't — Exodus only responds when you say "exodus." Deeper check anytime: npx exodus whoami shows which Exodus brand and account a folder is connected to.

This week's questions, answered

Do I paste my Genesis key into Exodus?

No. Never. Exodus linked its own Genesis access to your account by email when you onboarded. There is nothing to install, fix, or debug about Genesis keys inside Exodus. If an Exodus run fails, run npx exodus doctor and follow what it prints.

Is the Genesis key for Claude Code different from my OpenClaw key?

Same Genesis account, same kind of key. Your existing key keeps working everywhere you use it. Exodus separately maintains its own access — you don't manage that one.

What happens if I reset my Genesis API key?

Resetting your personal key affects the places you pasted it (OpenClaw, your .env, your scripts) — update those with the new key. It does not affect Exodus: its access is separate and survives your reset.

Can I register the Genesis server as an MCP server in Claude Code?

No — neither product is an MCP server. Genesis direct is a plain HTTPS API (your skills call it with a script); Exodus is a CLI (npx exodus …). If Claude suggests MCP configuration for either, that's a wrong turn.

Are the bots hardwired to 700+ word ads?

No. The full ad pipeline targets 700–1500 words because that's Luke's process for long-form DR ads — a design choice, and the editing menu (Shorten / Cut / Simplify) tightens any variant. Calling bots directly, the output is whatever your recipe asks for. Also: these bots are ad writers — DR ads, hooks, headlines from a brief, reel, or swipe. They're not general-purpose writers.

Why do Exodus runs take ~12–15 minutes? Is it "sequential"?

The pipeline currently writes variants one after another by design (hooks generate in parallel). That's an Exodus pipeline behavior, not a key limit — a faster parallel version is on the roadmap.

Exodus is using "random" product photos.

Not random — product photos from Settings → Brand Info attach only to ad formats whose brand-usage setting allows them ("brandy" formats). Native formats intentionally never use them, because native ads aren't supposed to look like brand ads.

Can Exodus swipe a video ad's script?

Today the swipe reliably captures the ad's primary text and headline; video transcripts are best-effort. If you want the video's script modeled, paste the script (or describe the beat) and Exodus uses it as steering. Full video-script swiping is the next build.

Do I need a separate brand/folder per product?

Yes, today: one Exodus brand = one folder, by design. The folder is how the CLI knows which brand you're working.

Where does Exodus's brand memory live? It's not reading my local files.

Correct — Exodus reads only its own primer, steering, and hook/headline banks (set in the dashboard or via npx exodus primer). Your local brand files belong to your own system. Want a rule applied to Exodus output? Put it in the Exodus primer steering. (A local-files import is on the wishlist.)

The skill file mentions files that aren't in my download. Missing?

Nothing's missing — the creative-strategy system builds its workspace as you use it. Primers, bot files, and the bot inventory are created by the skill during onboarding and use, not downloaded.

When something breaks

1. npx exodus update — you might be on an old version (old versions also have the old, collide-prone skills).

2. npx exodus doctor — it checks your setup and prints the fix.

3. Still stuck → post in the support channel with the doctor output. Don't let Claude "fix" keys, rotate credentials, or reconfigure servers on a hunch — the most common breakages are a missing update or a wrong folder, not keys.
