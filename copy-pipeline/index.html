01

The assembly line

One run, top to bottom. The big thing to know: once step 3 fires, nothing stops until the Doc is done. Every human choice today happens before the machine starts or after it finishes.

Before the machine — humans live here
1

The ask

Person

The customer wants ads. They hand over an idea, an Instagram reel, a competitor ad link, or a rough brief.

A Gate A — Idea approvalReview and refine captured ideas before any of them become a brief. (Half exists: the Idea Bank — but the one-shot "write from this reel now" commands skip it.)
2

The brief gets written

Local Claude

Claude Code writes a 1–2 paragraph brief from whatever the customer gave. There is no template and no rules — it improvises. It's supposed to show the brief as a "gut check," but nothing forces that or waits for a yes.

improvised — no skill, no schema
B Gate B — Brief approvalThe brief must be read and approved before the run can fire. Cheapest gate to build, and it guards the single most important input.
The machine — runs straight through, no stops

From here to step 14 there is currently no pause, no preview, no way to redirect. Fire and wait.

3

Fire

Local Claude

Claude Code runs the exodus genesis command. A run record is created. The button is pressed.

4

Safety check & handoff

Database

The backend checks the brand is ready (primer exists, the customer's AI keys work), takes a snapshot of the brand foundation, and hands the job to the cloud. It can fail here — but it can't pause.

5–6

Load seeds, pick the primer

Cloud script

Reads any creative seeds passed with the run, then picks the right primer for the awareness level (cold vs. warm). Your brand-level steering text rides along here.

7

Hooks — Mario voice

ad-hook-bot-1

Primed with the brand primer, fed the brief + hook bank + seeds. Writes ~20 hooks, then gets pushed once more for the visceral ones.

8

Hooks — Infeed voice

in-feed-vsl-bot

Same inputs, different voice. Another ~20 hooks. Both bots run at the same time.

▲ run in parallel → merged into one ~40-hook pool
9

Hooks get picked — by a script

Cloud script

A script — not a person, not a bot — picks the 2 most "diverse" hooks from the pool of ~40. The other 38 are discarded unseen. (A manual-pick override already exists in the code; nothing surfaces it to a human yet.)

easiest place to add a human
C Gate C — Hook reviewShow the human all ~40 hooks; they pick the ones the writers build on. The plumbing is half-built already. Also the natural place to split this into two pipelines: hooks → [human] → copy.
10

Body copy + headlines — Mario

mariobot

Gets the primer, then hook #1 woven into its instructions, plus the brief and headline bank. Writes 700–1500 words of body copy, then 4 headlines in the same conversation — there is no separate headline bot.

11

Body copy + headlines — Infeed

in-feed-vsl-bot

Same routine from hook #2. More passes requested = more rounds here (and a Top-Ads-flavored round on pass 2).

E Gate E — Draft reviewRead the raw variants before they're polished and shipped; kick weak ones back for a rewrite instead of receiving them in the finished Doc.
12

QA checklist

Cloud script

A 15-point automated check with auto-fixes. It's a checklist, not a judgment call — no taste involved.

13–14

The Doc is written & saved

Cloud script

Everything is formatted into a Google Doc — one tab per variant, hook merged into the full ad — and the run flips to "completed."

After the machine — humans again
15

Doc lands · edit menu opens

Person

The customer reads the Doc. They can now run per-variant edits — Natural-language / Shorten / Cut / Simplify / Make Better — each one a quick pass by the edit-pass bot. This is the only feedback loop that exists, and it comes after everything already ran.

Also existing today (soft controls, none of them block a run): curating the Idea Bank before writing · the unenforced brief "gut check" · brand-level steering text ("always do / never mention") that rides into every run.

02

Where the variety comes from

Two mechanisms, and the order matters: hooks are chosen before any copy exists, and each writer builds the ad around the hook it was handed.

Mechanism 1Hooks first, copy second

Two voices each write ~20 hooks. The pools merge into ~40. A script picks 2. Those 2 are injected into the writers' instructions — the hook is never bolted on afterwards.

≈40 hooks generated · 2 survive (yellow) · 38 discarded unseen

Mechanism 2Two writers, same brief

One "pass" = one variant from each voice, both writing from the brand primer. That's why the default output is 2 ads: same brief, two personalities.

03

Three doors, one machine

Gambit, organic, and swipe are not three pipelines. They're three capture doors that all deposit into the same Idea Bank — and from there, one identical path into the machine above. The bots never know which door an idea came through.

Door 1 · keys G1, G2…

Gambit

Customer brain-dumps raw angles as text. A splitter bot breaks the dump into distinct ideas.

bot: gambit-splitter
Door 2 · keys O1, O2…

Organic

Customer pastes an Instagram/TikTok reel. It's scraped, transcribed, on-screen text read — then a bot forms one idea from it.

bot: organic-idea-extractor
Door 3 · keys A1, A2…

Swipe

Customer pastes a Facebook Ad Library link. Copy, video transcript and on-screen text are scraped; a bot extracts the concept. Optional "what to model" steering rides along.

bot: swipe-concept-extractor
THE IDEA BANK every idea = a hook + a short concept + optional notes · the concept becomes the brief verbatim, the hook becomes a seed
▼  same escalation for all three  ▼
THE MACHINE (steps 3–14 above)
The one exception: writing from a previously saved competitor ad takes a completely different road — it skips the Idea Bank and the machine above entirely and runs through a separate "remix" pipeline. If you want all swipe-writing on one rail, that's a seam to deal with.
04

The brief problem

The most important input is the least defined step in the system.

There is no brief template, no rules, no check. The system accepts literally any text as a brief. The local Claude improvises one from whatever the customer said — so two customers asking for the same thing can get structurally different briefs. And when writing from a banked idea, there's no brief-writing at all: the idea's stored description ships to your bots word-for-word, as captured.

"If the user gave you an idea, a winning ad, or a rough angle, you write the brief from it; surface it for a quick gut-check before running." — the only brief 'rule' that exists today: a suggestion inside an instruction file
